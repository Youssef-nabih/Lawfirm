# تحديث واجهة مكتب المحاماة ومهام الشركات

## التشغيل
افتح index.html كالمعتاد. ملفات theme.css وworkspace.js يجب نشرها بجوار index.html وapp.js.

## تفعيل مهام الشركات
1. افتح مشروع Supabase المستخدم بالفعل في app.js.
2. من SQL Editor شغّل محتوى migrations/001_company_tasks.sql مرة واحدة.
3. افتح النظام بحساب معتمد، ثم إدارة الشركات ← ملف الشركة والمهام.

الملف ينشئ جدول company_tasks مستقلًا، مربوطًا بجدول companies، مع سياسات صلاحيات على مستوى الصفوف. يجب أن يكون جدول profiles الحالي متاحًا للمستخدم لقراءة ملفه، وجدول companies محميًا بسياسات الوصول المناسبة للمكتب؛ سياسات المهام تحترم الشركات المتاحة لذلك المستخدم.

المدير والموظف المعتمدان يستطيعان إدارة مهام الشركات التي يمكنهما رؤيتها. المستخدم المعتمد الآخر يعرض المهام فقط. حذف الشركة يحذف مهامها التابعة تلقائيًا. المهام العامة وإحصاءاتها تظل منفصلة.

بعد إضافة شركة جديدة يفتح ملفها مباشرة لإضافة مهامها. المهام تتضمن عنوانًا وتفاصيل وموعدًا وحالة إكمال. لا يتم حفظ أي بيانات مهام في التخزين المحلي.

## التحقق
تم اختبار CRUD وعزل الشركات وإعادة التحميل وعرض النصوص بأمان وحالة الجدول غير المفعّل والموبايل باستخدام قاعدة بيانات محاكاة في tests/workspace.cjs. لم يتم تشغيل ترحيل SQL على قاعدة حية أو اختبار صلاحيات RLS فعليًا؛ يلزم التحقق بحساب مدير وموظف وحساب غير معتمد بعد التفعيل.

لتشغيل اختبار الواجهة: node tests/workspace.cjs (يتطلب Playwright وMicrosoft Edge).

## النسخ الاحتياطي والاستعادة

بعد تفعيل مهام الشركات، شغّل `migrations/002_office_backups.sql` مرة واحدة في SQL Editor لنفس مشروع Supabase. ثم حدّث الموقع وسجّل الدخول بحساب مدير معتمد، وافتح «النسخ الاحتياطي» من القائمة الجانبية. يجب نشر `backup.js` مع بقية ملفات الموقع.

- نسخة البيانات تشمل الجداول السبعة: الشركات والموكلين والقضايا والجلسات والمصروفات والمهام العامة ومهام الشركات.
- النسخة بالمرفقات تشمل الملفات المرتبطة بحقول `_url` في هذه السجلات داخل bucket `documents`. لا تشمل الملفات اليتيمة أو الروابط الخارجية أو حسابات المصادقة أو ملفات الموظفين أو طلبات الانضمام أو إعدادات قاعدة البيانات والسياسات. هذه نسخة لبيانات عمل المكتب وليست نسخة بنية تحتية كاملة للمشروع.
- النسخة ملف JSON غير مشفّر، يحتوي تحقق SHA-256 لكشف التلف، وليس توقيعًا لإثبات مصدر الملف. احفظه بعيدًا عن مشاركة الملفات العامة.
- الأداة محدودة بـ100 MiB للملف النهائي لحماية ذاكرة المتصفح، وترميز المرفقات يزيد الحجم. الأرشيفات الأكبر تحتاج حل نسخ على الخادم. ليست هذه الميزة بديلًا عن النسخ الآلي المستقل للقاعدة والتخزين.
- الاستعادة لنفس المشروع وبنية الجداول، تضيف السجلات المفقودة وتستبدل المتطابقة وتحافظ على السجلات الأخرى. تحتاج الحسابات المشار إليها في البيانات إلى أن تظل موجودة. تغيير المشروع أو البنية يحتاج ترحيلًا بواسطة المسؤول.
- دوال التصدير والاستعادة تتحقق من دور المدير وحالة اعتماده وتعمل بصلاحيات المتصل وبسياسات RLS القائمة. يجب أن تسمح سياسات المكتب للمدير بقراءة كل سجلات المكتب وتعديلها. المساعد الوحيد الذي يعمل بصلاحيات المالك يضبط عدادات المعرفات للجداول المحددة بعد تحقق المدير.
- يتم رفع المرفقات المستعادة بأسماء جديدة، ثم تغيير روابط السجلات داخل معاملة واحدة. لا تُحذف المرفقات القديمة. إذا فشل رفع الملفات قبل محاولة حفظ البيانات تحاول الأداة تنظيف الملفات الجديدة؛ وإذا كانت نتيجة الحفظ غير مؤكدة بسبب الاتصال تحتفظ بها وتطلب التحقق قبل إعادة المحاولة.
- عند تغيير أي بيانات بعد المعاينة ترفض الاستعادة ويجب إعادة اختيار الملف للمعاينة مرة أخرى. نفّذ النسخ والاستعادة في وقت هادئ؛ العملية تستخدم أقفال جداول مؤقتة لضمان اتساق البيانات.

### تصدير Excel

زر «تصدير Excel» في قسم النسخ الاحتياطي ينشئ ملف XLSX بسبع أوراق عربية، مع اتجاه من اليمين لليسار وفلاتر وتثبيت للعناوين وأعمدة التعريف وصفوف متبادلة الألوان. تظهر أسماء الشركات والقضايا والموكلين بجانب سجلاتها المرتبطة. المبالغ أرقام، والتواريخ قابلة للفرز؛ المواعيد ذات المنطقة الزمنية تعرض بتوقيت القاهرة. أرقام الهواتف والتسجيل نصوص للمحافظة على الأصفار. تُصدّر الحقول الإضافية أيضًا.

المرفقات روابط وليست ملفات مضمّنة. الاستعادة تظل من JSON. يستخدم Excel دالة office_backup_export الموجودة في ملف التفعيل 002، ولا يحتاج SQL جديدًا بعد تشغيلها. يجب نشر excel-export.js ومجلد vendor مع الموقع؛ المكتبة محلية وتُحمّل عند الطلب فقط.

اختبار المتصفح يفحص XLSX بعد تنزيله وفتحه ثانية: الأوراق والأنواع والروابط والأصفار والحقول الإضافية والتثبيت والفلاتر ومنع تحويل نصوص المستخدم إلى صيغ والتصدير الفارغ. تمت مراجعة صور أوراق عينة اصطناعية بأداة Artifact Tool؛ عارضها لا يحاكي اتجاه العربية والأرقام النصية بدقة، لذلك تم فحص القيم والخصائص مباشرة في XLSX. لم يتوفر Microsoft Excel محليًا لاختبار العرض الأصلي.

### اختبارات النسخ
`node tests/backup.cjs` يختبر واجهة المتصفح بقاعدة وتخزين محاكيين: النسخة بالمرفقات، SHA-256، الموافقة، ملفات تالفة أو من مشروع آخر، تغيّر البيانات، أخطاء التنزيل، صلاحية المدير والموبايل.

`node tests/backup-sql.cjs` يختبر ملفات SQL على PostgreSQL محلي عبر PGlite: التصدير، الاستعادة، التراجع عند فشل جدول، الحفاظ على السجلات الأخرى، عدادات المعرفات ومنع غير المدير. حزمة الاختبار مثبتة في مجلد النظام المؤقت `lawfirm-backup-sql-test`، ولا تُستخدم في الموقع. لم يتم تطبيق التهيئة أو اختبار الصلاحيات الفعلية على مشروع Supabase الحي.

## الأنشطة — للمدير فقط

شغّل `migrations/003_activity_log.sql` مرة واحدة في SQL Editor بمشروع Supabase، بعد ملف 001، وانشر `activity.js` مع ملفات الموقع المعدلة. لم يُطبّق هذا الترحيل على المشروع الحي من خلال هذه المهمة.

تظهر «الأنشطة» بجوار الموظفين للمدير المعتمد، مع اسم منفذ العملية واسم المستخدم ونوع العملية والقسم والسجل وعدد الحقول المتغيرة ووقت القاهرة. تتوفر فلاتر الاسم والعملية والقسم وصفحات من 50 نشاطًا. يشمل السجل تغييرات المدير أيضًا، والعمليات دون مستخدم تظهر باسم «النظام».

التسجيل يتم عبر triggers داخل معاملة التغيير للجداول السبعة: الشركات والموكلون والقضايا والجلسات والمصروفات والمهام ومهام الشركات. تُسجّل الإضافة والتعديل والحذف الناجحة فقط، ويُتجاهل التعديل الذي لا يغير شيئًا، وتُلغى الأنشطة إذا تراجعت المعاملة. تبقى هوية المنفذ واسم السجل بعد حذف السجل الأصلي. لا يحفظ السجل نسخة كاملة من قيم البيانات؛ يحتفظ بأسماء الحقول المتغيرة فقط.

سياسة RLS تسمح بالقراءة للمدير المعتمد فقط، ولا يملك مستخدمو التطبيق صلاحية إضافة أو تعديل أو حذف أنشطة مباشرة. يفترض المشروع مكتبًا واحدًا وفق بنية الجداول الحالية. لا يشمل السجل تصفح الصفحات أو تسجيل الدخول والخروج أو تنزيل وتصدير الملفات أو رفع ملفات يتيمة أو تغييرات حسابات الموظفين، ولا يعيد إنشاء العمليات السابقة للتفعيل. تعديل روابط المرفقات داخل الجداول مشمول. استعادة البيانات تولّد أنشطة للتغييرات التي تنفذها، لكن سجل الأنشطة نفسه ليس ضمن ملف النسخ الاحتياطي الحالي.

التحقق: `node tests/activity-sql.cjs` يختبر PostgreSQL عبر PGlite (بنفس الاعتماد المؤقت المستخدم لاختبار النسخ)، و`node tests/activity.cjs` يختبر الواجهة عبر Playwright وEdge. تشمل الاختبارات صلاحيات المدير والموظف وغير المعتمد والزائر، ومنع العبث بالسجل، والتراجع والتعديلات دون تغيير، والفلترة والصفحات وعرض النصوص بأمان وتغيّر الصلاحية أثناء الطلب. يلزم تطبيق الترحيل والتحقق على مشروع Supabase الفعلي للتفعيل.

## توحيد وقت الجلسات

وقت إدخال وعرض الجلسات ثابت على `Africa/Cairo` بغض النظر عن توقيت جهاز المستخدم. عند الحفظ يتحول موعد القاهرة إلى UTC مع مراعاة الصيفي والشتوي. كان حقل التعديل يقص أول 16 حرفًا من التوقيت المخزن دون تحويل، بينما العرض يستخدم توقيت الجهاز، والحفظ يرسل وقتًا دون منطقة زمنية؛ وهذا يسبب اختلاف العرض والتعديل وانزياح الموعد عند إعادة الحفظ.

الإصلاح في `app.js` و`index.html` ولا يحتاج SQL. يحتفظ حفظ الموعد غير المتغير بالقيمة الأصلية بما فيها الثواني والمنطقة الزمنية. التوقيت القديم بدون منطقة زمنية يعامل كوقت القاهرة. الساعة غير الموجودة عند بدء التوقيت الصيفي تُرفض؛ والساعة المكررة في نهايته تستخدم أول ظهور عند إدخال موعد جديد. لا تُعدّل البيانات القديمة تلقائيًا: راجع الموعد المقصود للجلسات التي سبق إدخالها بالنظام القديم ثم صححه عند الحاجة.

`node tests/session-time.cjs` يتحقق من فرق الصورة، والإدخال والحفظ والعرض في الصيف والشتاء وعبر منتصف الليل، وثلاث مناطق زمنية للجهاز، وحفظ القيمة الأصلية، ورفض ساعة انتقال صيفي غير موجودة.

## صفة أطراف القضية

قبل نشر تحديث صفة الموكل وصفة الخصم، شغّل `migrations/004_case_party_roles.sql` في SQL Editor بمشروع Supabase. يضيف عمودين اختياريين دون تغيير بيانات القضايا القديمة أو صلاحياتها. لم يُطبّق الملف على المشروع الحي هنا. تظهر الصفة في الإضافة والتعديل والجدول والتفاصيل وتصدير Excel، مع اقتراحات وإمكانية كتابة صفة أخرى.

## تجربة المكتب الجديدة

انشر `experience.js` و`experience.css` مع الملفات الحالية. تشمل الرئيسية أجندة الجلسات بتوقيت القاهرة، المهام العامة المتأخرة، وبطاقات القضايا مع البحث بالاسم والموكل والرقم والمحكمة. يعرض ملف القضية ملخصًا والجلسات كتسلسل زمني، مع شريط تنقل للموبايل. لا يحتاج التحديث ترحيل SQL، ويستخدم صلاحيات وجداول النظام الحالية. تعرض الرئيسية أول 12 قضية مطابقة وأول 20 جلسة في الفترة المختارة؛ مهام الشركات تظل في ملفات الشركات.

للمعاينة المحلية المنفصلة ببيانات اصطناعية: `node tests/build-preview.cjs` ثم `node tests/serve-preview.cjs` وافتح `http://127.0.0.1:4173/`. المعاينة لا تتصل بقاعدة المكتب، وليست صفحة تشغيل حقيقية. لا تنشر مجلد preview على أنه النظام الأساسي.

التحقق: `node tests/experience.cjs` يفحص الجلسات والأولويات والبحث والتسلسل الزمني والإغلاق بلوحة المفاتيح والعرض على الموبايل والحالات الفارغة وعرض النصوص بأمان. تم كذلك تشغيل اختبارات workspace وcase-roles وsession-time. لم يتم اختبار هذا التحديث على قاعدة الإنتاج.

## تمييز المهام المهمة جدًا

شغّل `migrations/005_task_importance.sql` في Supabase SQL Editor قبل نشر التحديث. يضيف `is_important` إلى المهام العامة ومهام الشركات (إن كان جدولها موجودًا)، بقيمة افتراضية false للسجلات القديمة، دون تغيير الصلاحيات. إذا فُعّلت مهام الشركات لاحقًا، أعد تشغيل 005. لم يتم تشغيل الملف على قاعدة البيانات الحية من هذه المهمة.

اختر «★ مهمة جدًا» عند الإضافة أو التعديل لتظهر المهمة بالذهبي مع شارة نصية. يمكن إلغاء الاختيار من التعديل. تبقى العلامة محفوظة عند إكمال المهمة. تعرض الرئيسية المهام العامة المهمة جدًا غير المكتملة ضمن الأولويات حتى قبل موعدها. يظهر الحقل باسم عربي في Excel، وتشمله النسخ الجديدة تلقائيًا. احتفظ بنسخة قبل الترحيل وأنشئ نسخة جديدة بعده؛ النسخ القديمة تختلف في توقيع بنية الجداول ولا تستعاد مباشرة بعد تغيير البنية.

اختبار `node tests/task-importance.cjs` يغطي الحفظ وإعادة التحميل وإلغاء العلامة والإكمال ومهام الشركات وصلاحية العرض والموبايل بقاعدة محاكاة.
